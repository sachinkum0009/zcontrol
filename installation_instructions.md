# Z Control — installation instructions

Toolchain needed to build and flash Z Control firmware for the ESP32-S3
(`zenoh-nostd` + embassy + `esp-hal`) and to run the virtual device on the host.

Versions installed and tested on 2026-10-12:

| Tool | Version | Purpose |
|---|---|---|
| `rustup` / Rust stable | 1.99.0 | Host crates, `std` virtual device, tests |
| `espup` | 0.17.1 | Installs the Xtensa Rust toolchain |
| Rust `esp` toolchain | 1.97.0.0 (Xtensa) | ESP32-S3 builds (`cargo +esp`) |
| Xtensa GCC | esp-15.2.0_20250920 | Linker for `xtensa-esp32s3-none-elf` |
| Xtensa LLVM (libclang) | esp-20.1.1_20250829 | Required by the `esp` toolchain |
| `espflash` | 4.6.0 | Flash and monitor the board |
| `zenoh-nostd` | git `e88f73a` (2026-06-26) | MSRV 1.91.0 — both toolchains satisfy it |

## Option A — workspace-local install (what this dev container uses)

The container root disk is almost full and is lost when the container is
rebuilt, so the toolchain lives in the workspace mount:

```
plotbot3_ws/.toolchains/
├── rustup/          RUSTUP_HOME (stable + esp toolchains)
├── cargo/           CARGO_HOME  (cargo, rustup, espup, espflash binaries)
├── tmp/             TMPDIR (/tmp is mounted noexec in the container)
├── export-esp.sh    generated by espup (Xtensa GCC PATH + LIBCLANG_PATH)
├── env.sh           source this in every new terminal
└── ref/zenoh-nostd  upstream clone, for reading examples
```

Use it:

```bash
source /media/asus/backup/zzzzz/ros2/b_robotized/workspaces/plotbot3_ws/.toolchains/env.sh
```

Optionally add that line to `~/.bashrc`.

### Reinstall from scratch

```bash
WS=/media/asus/backup/zzzzz/ros2/b_robotized/workspaces/plotbot3_ws
TC=$WS/.toolchains
mkdir -p $TC/tmp
export RUSTUP_HOME=$TC/rustup CARGO_HOME=$TC/cargo TMPDIR=$TC/tmp
export PATH=$CARGO_HOME/bin:$PATH

# 1. Rust stable (TMPDIR matters: rustup-init cannot run from a noexec /tmp)
curl --proto '=https' --tlsv1.2 -sSf https://sh.rustup.rs -o $TC/rustup-init.sh
sh $TC/rustup-init.sh -y --no-modify-path --profile minimal \
   --default-toolchain stable -c rustfmt,clippy

# 2. espup + espflash prebuilt binaries (avoids building espflash, which needs libudev-dev)
curl -sSL -o $CARGO_HOME/bin/espup \
  https://github.com/esp-rs/espup/releases/download/v0.17.1/espup-x86_64-unknown-linux-gnu
chmod +x $CARGO_HOME/bin/espup
curl -sSL -o $TC/tmp/ef.zip \
  https://github.com/esp-rs/espflash/releases/download/v4.6.0/espflash-x86_64-unknown-linux-gnu.zip
python3 -c "import zipfile;zipfile.ZipFile('$TC/tmp/ef.zip').extractall('$CARGO_HOME/bin')"
chmod +x $CARGO_HOME/bin/espflash && rm $TC/tmp/ef.zip

# 3. Xtensa toolchain for the ESP32-S3 only
espup install --targets esp32s3 --export-file $TC/export-esp.sh
```

Then write `env.sh` (already in the workspace) and source it.

Disk usage: about 2.5 GB for `rustup/`, plus `target/` directories per project
(about 1 GB per ESP32 build profile).

Note: `espup` also creates the symlink `~/.espup/esp-clang` in the home directory.
It is only a convenience link, and `LIBCLANG_PATH` in `export-esp.sh` points to the real path.

## Option B — standard install (any other Linux machine)

```bash
curl --proto '=https' --tlsv1.2 -sSf https://sh.rustup.rs | sh
cargo install espup --locked          # or download the prebuilt binary as above
espup install --targets esp32s3       # writes ~/export-esp.sh
cargo install espflash --locked       # needs: sudo apt install libudev-dev pkg-config
echo '. ~/export-esp.sh' >> ~/.bashrc
```

## Verify the toolchain

Build the upstream `z_pub` example for the ESP32-S3. A successful link proves
that Rust, the Xtensa toolchain, GCC and `zenoh-nostd` all work:

```bash
source $WS/.toolchains/env.sh
cd $WS/.toolchains/ref/zenoh-nostd
WIFI_PASSWORD=dummy cargo +esp --config .cargo/config.esp32s3.toml \
  build --release --no-default-features --features=esp32s3,defmt --example z_pub
```

Expected: `Finished release profile`. The linker warning
`LOAD segment with RWX permissions` is normal for ESP32 images.

## Flashing: USB access to the board

The ESP32-S3 shows up as `/dev/ttyACM0` (native USB) or `/dev/ttyUSB0` (USB-UART bridge).

1. **On the host machine** (not in the container), give your user access:
   ```bash
   sudo usermod -aG dialout $USER     # log out and in again
   ```
2. **Pass the device into the dev container.** It must be visible inside the
   container, either via `--device=/dev/ttyACM0`, or `-v /dev:/dev` together with
   `--device-cgroup-rule='c 166:* rmw'` (ttyACM) and `'c 188:* rmw'` (ttyUSB),
   so that re-plugging the board keeps working.
3. Check it from inside the container:
   ```bash
   ls -l /dev/ttyACM* /dev/ttyUSB*
   espflash board-info
   ```

Status 2026-10-12: no board is visible in the container yet, and the user is not
in `dialout`. Both steps above are still needed before the first flash.

If flashing fails to connect: hold **BOOT**, tap **RESET**, release **BOOT**, then retry.

## Zenoh router on the host

The ESP32 runs zenoh in client mode and needs a router on the host. The ROS 2
Jazzy install already contains one:

```bash
ros2 run rmw_zenoh_cpp rmw_zenohd        # listens on tcp/[::]:7447
```

The board connects to `tcp/<host-ip>:7447`. The host must be reachable from the
WiFi network the ESP32 joins, and the container must use host networking or
publish port 7447.
